# ONECUE 홈페이지 개발킷 (v4, 2026-10-02)

이 문서는 ONECUE 홈페이지 시안을 실제 홈페이지에 옮기는 개발자(또는 개발을 맡은 Claude)를 위한 인수인계 문서입니다.
시안은 이미 완성된 단일 HTML 파일이고 외부 라이브러리 없이 동작합니다. 목표는 "디자인·카피·스크롤 동작을 그대로 유지하면서" 실제 도메인과 문의 흐름에 연결하는 것입니다.

- 받기: `git clone https://github.com/Hoon712-code/onecue-devkit.git` 또는 압축본 https://github.com/Hoon712-code/onecue-devkit/releases/download/v4/onecue-devkit.zip
- 실제 동작 데모: https://claude.ai/artifact/7RQs3VAq4gwjYhqaSfQV8Q
- 레퍼런스(스크롤 연출 원본): https://www.secretlevel.co/

## 1. 파일 구성

```
site/
  index.html            완성 페이지 (HTML + CSS + JS 한 파일, 약 28KB)
  engine.reference.js   index.html 안 <script> 와 같은 코드 (읽기용 사본)
  media/                영상·이미지 30개 (약 20MB)
    NN-name.mp4         PC 배경 영상 1600x900
    NN-name-m.mp4       모바일 배경 영상 540x960
    NN-name.jpg         PC 포스터 (영상 로딩 전 첫 화면)
    NN-name-m.jpg       모바일 포스터
    NN-name-thumb.jpg   왼쪽 장면 레일 썸네일 320x180
```

장면 6개: 01-hero, 02-problem, 03-solution, 04-price, 05-speed, 06-start

`site/` 폴더를 그대로 정적 호스팅에 올리면 바로 동작합니다. 빌드 과정은 없습니다.

## 2. 가장 먼저 할 일 (적용 순서)

1. `site/` 를 그대로 올려 실제 도메인에서 동작부터 확인 (맥 트랙패드, 윈도우 마우스 휠, 아이폰 사파리, 안드로이드 크롬)
2. 아래 4절 "연결해야 할 링크" 의 `href="#"` 를 실제 경로로 교체
3. `<head>` 에 메타 태그 추가 (5절)
4. 프레임워크(Next.js 등)로 옮겨야 한다면 9절 규칙을 지킬 것. 옮기지 않아도 되면 정적 HTML 그대로 쓰는 것을 권장
5. 10절 테스트 항목 전부 통과 확인

## 6. 디자인 시스템

### 색·폰트 토큰 (`:root`)

| 토큰 | 값 | 용도 |
|---|---|---|
| --bg | #0d0d0e | 바탕 |
| --ink | #f4f2ef | 글자 |
| --accent | #d7ff3a | 형광 라임. 점·활성 상태·강조 숫자·주 버튼 |
| --sans | Pretendard | 한글 헤드라인·본문 |
| --mono | IBM Plex Mono (+Pretendard) | 라벨·본문·버튼·내비 |
| --disp | Anton | 영문 대문자(로고, 모바일 메뉴) |
| --padL | clamp(150px,19vw,280px) | PC 왼쪽 여백 (장면 레일 공간) |
| --padR | clamp(24px,5vw,80px) | 오른쪽 여백 |

- 다크 단일 테마입니다 (라이트 모드 없음, 의도된 결정).
- 반응형 기준점은 819px 하나입니다. 이하이면 모바일: 모바일 영상(`video.m`)으로 바뀌고, 상단 내비 대신 MENU 버튼, 왼쪽 레일 숨김, 카피 가운데 정렬.
- 모바일 높이 760px 이하에서는 `.body` 본문을 숨겨 헤드라인이 잘리지 않게 합니다.
- 헤드라인 크기는 장면마다 인라인 `clamp()` 로 따로 맞췄습니다. 카피 길이를 바꾸면 PC·모바일 줄바꿈을 다시 확인해야 합니다.
- 영상 위 글자 가독성: 장면마다 `.shade` 그라디언트(왼쪽이 어두움) + 헤드라인 text-shadow. 영상 자체도 카피 뒤쪽(PC 왼쪽, 모바일 가운데 띠)은 흐리고 느리게 만들어 두었습니다.

### 화면 고정 요소

- 좌상단 로고, 상단 가운데 유리질감 내비(Why/How/Price/Speed/Start), 우상단 "10만원부터 의뢰" 버튼
- 왼쪽 세로 장면 레일: 썸네일 6개, 현재 장면에 라임 테두리, 클릭하면 해당 장면으로 이동

- 장면이 활성화(`.scene.on`)될 때 취소선·범위 막대·비교 막대가 그려지는 진입 애니메이션 (CSS transition)

## 7. 스크롤 엔진 사양 (핵심 기능)

페이지는 브라우저 기본 스크롤을 쓰지 않습니다 (`html,body{overflow:hidden}`, `.stage{position:fixed}`).
휠·터치 입력을 직접 받아 장면 6개를 무한 루프로 넘깁니다. 레퍼런스 secretlevel.co 의 연출을 측정해서 같은 값으로 맞췄습니다.

### 연출

- 장면 박스는 입력량만큼 실제로 위아래로 밀립니다 (`translateY(o*화면높이)`, o = 현재 위치와의 차이 -1~1).
- 박스 안쪽 `.inner` 에 추가 변형: 나가는 장면은 커지고(최대 1.29배) -7도 기울고, 위로 지연 이동(180px@900px 높이 기준)하며 50%까지 어두워집니다. 들어오는 장면은 반대(+7도)에서 바로 섭니다.
- 상수: `SC = 0.29` (확대), `ROT = 7` (회전 각도), `LAG = 180` (지연 이동), `DIM = 0.5` (어두워짐)
- 움직임 보간: 지수 감쇠. 시간상수 0.22초 (터치 중에는 0.045초로 손가락을 바로 따라감)
- `prefers-reduced-motion` 이면 회전·확대 없이 단순 크로스페이드

### 입력 규칙

| 입력 | 동작 |
|---|---|
| 마우스 휠·트랙패드 | 입력량만큼 따라 움직이고, 140ms 입력이 없으면 5% 이상 민 방향으로 스냅 |
| 트랙패드 관성 | 한 번 쓸기 = 최대 한 장면 (관성으로 두 장씩 넘어가지 않음) |
| 연속 스와이프 | 관성이 남아 있어도 새로 쓸면 즉시 다음 장면 (아래 설명) |
| 터치 | 손가락을 따라 움직이고, 빠르게 튕기면(0.35px/ms 이상, 20px 이상) 다음 장면, 아니면 12% 기준 스냅 |
| 키보드 | ↓ PageDown Space = 다음, ↑ PageUp = 이전, Esc = 메뉴 닫기 |
| 내비·레일·메뉴 | 가까운 방향으로 해당 장면 이동 (6 → 1 은 아래로 한 칸) |
| 마지막 장면에서 아래로 | 첫 장면으로 이어짐 (무한 루프) |

### 맥 트랙패드 처리 (반드시 유지)

맥 트랙패드는 손을 뗀 뒤에도 관성 휠 신호가 끊김 없이 이어집니다.
초기 버전은 "신호가 끊겨야 새 제스처" 로 판단해서, 관성이 남아 있는 동안 스크롤이 먹히지 않는 버그가 있었습니다 (화면 클릭해야 풀림).
현재 코드는 다음 중 하나면 새 제스처로 봅니다:

- 신호가 150ms 이상 끊김
- 신호 세기가 직전 최고치(서서히 감쇠시킨 값)의 1.15배+2 보다 커짐 = 새로 쓸어 올림
- 세기 40 이상이면서 직전보다 같거나 커지고 30ms 이상 간격

변수 `spent`, `peak`, `prevAb`, `lastWheel` 로 구현되어 있습니다. 이 부분을 다른 스크롤 라이브러리(Lenis, fullPage.js 등)로 바꾸지 마세요. 같은 문제가 다시 생깁니다.

### 영상 재생 관리

- 현재 장면과 앞뒤 한 장면(±1)의 영상만 재생, 나머지는 일시정지
- 첫 장면만 `preload="auto"`, 나머지는 `none` 으로 시작해 가까워질 때 로드
- PC/모바일 영상은 둘 다 DOM 에 있고 미디어쿼리로 보이는 쪽만 재생
- 탭이 숨겨지면 전부 정지

## 8. 미디어 규격

| 종류 | 규격 |
|---|---|
| PC 영상 | H.264 High, 1600x900, 30fps, 12초 루프, 약 1.4Mbps, 오디오 없음, 1.6~3.0MB |
| 모바일 영상 | H.264 High, 540x960, 30fps, 12초 루프, 약 0.45Mbps, 오디오 없음, 0.7~1.2MB |
| 포스터 | 영상 0.5초 프레임 JPG (PC 1600x900, 모바일 540x960) |
| 썸네일 | 320x180 JPG |

- 영상은 ONECUE 기존 제작 광고 클립(환타·블렌디·아쿠아베일 등)을 편집해 만들었습니다. 카피가 놓이는 영역은 일부러 흐리고 느리게 처리했으므로, 영상을 교체할 때도 이 원칙(카피 뒤는 차분하게, 움직임은 반대편에)을 지켜주세요.
- CDN 에 올릴 경우 mp4 는 `Accept-Ranges` (range 요청) 를 지원해야 아이폰에서 재생됩니다.
- `muted playsinline autoplay` 속성은 iOS 자동재생 조건이므로 지우면 안 됩니다.

## 9. 프레임워크로 옮길 때 (Next.js 등)

- 마크업 구조(`.stage > section.scene > video + .shade + .wrap`) 와 클래스명을 그대로 유지하세요. 엔진이 `.scene` 의 자식들을 `.inner` 로 감싸는 방식이라 구조가 바뀌면 연출이 깨집니다.
- 엔진 코드는 클라이언트에서 DOM 이 그려진 뒤 한 번만 실행 (React 면 `useEffect` 1회, cleanup 에서 이벤트 리스너 제거). React 가 `.scene` 의 자식을 다시 그리면 `.inner` 가 사라지므로, 장면 내부는 정적 마크업으로 두는 것을 권장합니다.
- wheel·touchmove 리스너는 `{ passive: false }` 여야 합니다 (기본 스크롤 차단).
- 이 페이지는 한 화면 고정 구조라 다른 페이지(가격표, 의뢰 폼)는 별도 라우트로 두는 것이 맞습니다.
- 가장 안전한 방법은 이 HTML 을 그대로 홈(`/`)으로 쓰고, 나머지 페이지만 프레임워크로 만드는 것입니다.
